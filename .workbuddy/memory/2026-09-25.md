## 第二份：Agent 功能与 UI 建议

产出：`doc/Agent 功能与 UI 建议.md`（功能 10 条 + UI 13 条，带 file:line）。

新核验到的关键事实：
- **ScriptService 是死代码**：`fetchScriptList()` / `downloadAndInstall()` 全仓库无调用方，但 README 已经把「从在线脚本库下载」当卖点。接上它就是「下载 → 作为基线改 → 覆盖/另存」的闭环。
- **脚本运行期报错写在 `<脚本目录>/error.txt`**（`PluginError.kt:28,52`），而该目录正是 `read_file` 的允许范围 → 「读报错自愈」几乎零成本。
- **`buildExistingScriptContext`（`PluginViewModel.kt:917-940`）不发 info.prop**，模型不知道当前脚本的 id/版本/作者，写回的新 info.prop 很可能换 id，进而让 `pluginId == editId` 的基线判断失配（与第一份 P0-2 互为因果）。
- 校验三件套都是现成的：`bsh.Parser.Line()` 可只解析不执行；`PluginCallback.kt:19-90` 给出真实回调签名表；`PluginMethod` 64 个公开方法可反射成白名单。
- UI：`AgentPage.kt` 1843 行 / 30 个私有 composable；生成中 send 被替换为 cancel 且 `sendAgentMessage` 早退（不能排队下一条）；代码查看器无搜索；保存对话框名称默认空。

项目约定（后续沿用）：建议文档统一写到 `doc/` 下，中文、带优先级与 file:line 定位。
